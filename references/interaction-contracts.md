# 交互契约

用于控件、表单、导航、异步状态和移动交互。沿用项目已有且经过验证的原语，避免手写一个不完整的“看起来像按钮”的控件。

## 控件的可观察行为

| 对象 | 必须成立 |
|---|---|
| 动作与导航 | 动作用 button、导航用有目标的链接；按钮类型明确，不能误提交表单 |
| 单选与开关 | 同一维度只选一个；不同维度分组；选择、切换、页面导航不能混用相同语义 |
| 输入 | 有常驻 label；说明和错误关联输入；placeholder 不代替标签；校验错误与网络失败分开 |
| 焦点 | 键盘可达、可见、顺序合理；不能只测 focus 时文字颜色；不被固定栏或裁切容器遮住 |
| 弹窗 | 有可访问名称、合理初始焦点、关闭路径；模态内限制焦点，关闭后回到触发点或合理后继 |
| 图标控件 | 可访问名称表达动作；装饰图标不重复朗读；触控区域不只覆盖小图标 |
| 禁用与忙碌 | 原生 disabled 阻止操作；aria-disabled 只提供语义，还需处理事件；aria-busy 不自动防重 |
| 错误与成功 | 就近说明发生什么、保留了什么、下一步能做什么；状态变化可被辅助技术感知 |

优先 native input/radio/select/dialog 或现有组件库。自定义 tabs、menu、combobox 时实现对应键盘模式，不是加一个 role 就完成。不要使用正 tabindex 重排焦点或删除 outline 而不提供替代。

表单校验失败可把焦点移到首个无效字段或错误摘要；网络失败不应自动清空输入、标记合法字段为无效或把焦点拉走。密码、令牌等敏感输入不因“保留上下文”写入持久存储。

## 提交快照与当前草稿

区分当前可编辑值、本次提交的不可变输入和服务端确认结果。使用现有表单库传入的提交数据或在合法提交时捕获快照；异步完成后不能重读输入框，倒推刚才发送了什么。提交范围还包括对象、账户和版本；不把密码、令牌或完整个人信息放进通知／日志证明归属，按需要使用安全对象名或脱敏摘要。

提交中是否允许继续编辑按任务决定，不一律锁住整页。允许编辑时，新草稿必须保留；A 的响应不能重置 B、把 B 标成已保存或给 B 显示只针对 A 的字段错误。界面就近区分本次结果和未提交改动，重试旧快照与提交新草稿必须明确，不能都写成含糊的“重试”。成功判断依据服务端确认，而不是按钮禁用解除或 Promise 未抛错；是否更新表单基准值按当前模型与返回版本处理，不盲目整表 reset。

字段格式错误、服务器字段校验与连接失败分别呈现。过期的字段错误只在相应输入／版本仍适用时关联字段；请求失败不把合法邮箱标为无效。提交反馈包含必要对象上下文，但不夺走用户正在编辑处的焦点。输入变更只在未提交状态变化时更新提示，不每键重建 live region 反复朗读整个结果。

验证覆盖提交 A→等待期间改 B→A 成功／失败、完成后继续编辑、改回同值、重试新草稿、原生校验及重复提交。`preview.html` 仅以单个邮箱的字面值比较演示此策略，不代表多字段归一化、服务端字段错误或真实保存。源码依据见 [第十五轮调研](research-2026-10-02-round15.md)。

## 阅读型弹窗：起点、滚动区与退出入口

先根据任务选择初始焦点。阅读详情有多段、列表或长正文时，焦点放到内容起点的静态标题／首段（如 `tabindex="-1"`），不要为聚焦尾部第一个按钮而把开头卷走。编辑表单、短确认与不可逆操作各按任务选择字段、常用操作或安全动作，不把“所有弹窗聚焦标题”写成通用规则。只在打开或确有必要的上下文切换时转移焦点，不随每次渲染重新聚焦。

明确谁负责滚动：整层覆盖区滚动、整个弹窗滚动、或正文局部滚动都可行，依照现有框架和内容选择。正文与操作区分离时，正文能收缩且确实可滚动，末段不能被操作区覆盖；不要只在外壳加 `overflow:hidden` 却没有提供可到达全文的滚动路径。尺寸同时受可用宽度和高度约束；矮屏／横屏也是正常条件，不删除费用、风险或退出入口来腾空间。短内容保持自然高度，不为长内容预留整屏空白。

验证打开时能看到阅读起点、滚动中与末尾能找到退出入口、键盘能滚动正文并到达按钮、关闭后返回有效触发器。原生 `<dialog>` 保留关闭态语义，布局规则限定在打开态，不以无条件 `display:flex` 让关闭窗口继续显示。长内容测试使用真实控件结构并明确标记注入数据；窗口变矮不等于实体软键盘已测试，DOM焦点正确也不等于读屏已验收。

本例采用原生对话框、正文滚动和非滚动操作区；Radix Themes 采用覆盖层滚动，不能称为同一实现。依据与取舍见 [第十六轮调研](research-2026-10-02-round16.md)。

## 组合浮层：一份关闭责任与一份焦点责任

对话框内打开菜单、日期选择器或二级确认时，先确定当前活动层、父层和关联触发器。一次 Escape 由当前应处理该键的最上层消费；取消关闭也不能继续穿透关闭父层。先保留输入法、编辑器及已消费事件的处理权，不能因参考库用了捕获监听就删除现有退让规则。

焦点限制、背景不可操作和视觉堆叠分别验证。打开子模态时父级焦点限制需要让位，子层关闭后恢复到仍有效的父级控件；父层已关闭或触发点失效时选择合理后继，不执行迟到的自动回焦。非模态面板不因处在上层就被加上焦点陷阱。

通过 portal 渲染到别处的子菜单，仍可能属于当前交互范围。不能只用父节点 `contains(target)` 判定“外部点击／焦点逃逸”；优先使用已有原语的分支登记、关联浮层或逻辑事件边界。同时不能把整个 body 当合法分支，否则背景隔离失效。内嵌与 portal 两种挂载都要能选择、返回，焦点不能在父子层之间反复抢夺。

触摸滚动、拖动、取消手势与确认的外部点击分开；关闭不应让同一次手势穿透触发背景危险操作。背景滚动／指针锁按持有者恢复：子层关闭不能提前解锁仍存在的父模态，最后一层关闭也不能遗留整页不可点击。不要用全局 stopPropagation、增加 z-index 或永久禁用背景“修复”这些关系。

只有本次涉及组合浮层才展开这些检查；简单按钮不需新增层管理器。已有库优先，不并建第二套全局事件栈。Radix 的实现依据与移植边界见 [第十一轮调研](research-2026-10-01-round11.md)。

## 异步状态不是几个颜色

| 状态 | 呈现与行为 |
|---|---|
| 未请求／加载 | 说明还未得到结果；必要时占位，不显示真实的 0 |
| 成功且为空 | 明确无记录或无匹配；给清除筛选／创建等真实动作 |
| 成功有数据 | 使用权威返回值；需要时显示来源或更新时间 |
| 查询失败 | 明确未读到结果，提供重试；已有旧数据可保留但标明过期或刷新失败 |
| 提交中 | 立即反馈并防止同一动作重复执行；不要顺便禁用无关导航 |
| 提交失败 | 只有确定失败才提供可安全重试的提交；保留安全输入 |
| 结果未确认 | 超时不等于失败，特别是订单／付款；先查询现有操作，不诱导再次扣款 |

快速切换筛选、页面或账户后，旧请求不能覆盖当前视图。先区分**数据身份、请求身份和提交范围**：结果身份覆盖决定数据的非敏感授权范围、查询、排序和分页语义；缓存键与页参数按现有库的契约组织，不强制将追加游标放进列表基础缓存键。同一键也可能发起多次请求，A→B→A 不代表第一次 A 自动重新有效。用已有查询层／路由器的身份机制，不重复建立控制器；独立面板的请求不能因为别处开始加载而互相取消。不要把原始令牌或私人查询复制进日志来证明隔离。

**取消是资源管理，结果是否仍可提交是状态正确性。** 传输可能忽略 signal，成功、错误、分页追加及 finally 都须服从当前提交域。旧 finally 不能关掉新加载提示；取消错误按真实请求归属判断，不能仅凭名字为 AbortError 就吞掉当前真实失败。已失效的视图不能更新，不等于所有未显示查询必须取消或禁止正确写入各自隔离的缓存。TanStack Query 默认允许某些未使用请求完成后留在缓存；缓存复用、在途去重与本地“最新请求优先”是不同策略，不混成一条全局规则。

同一查询中区分首次读取、刷新／排序和追加页。首次未返回不展示假零；已有且仍有权限的内容可保留时，刷新反馈不替换整张表；下一页失败在追加入口重试，不清空已读结果。切换条件后保留旧画面时，显式区分请求中的条件与当前数据的条件／时点；有占位旧数据不等于已取得新结果。库的 success 可能同时伴随 isPlaceholderData；不能据此把旧页 hasMore、费用、导出范围或汇总当成新页事实。账户／权限变化先隔离旧内容。React Spectrum reload 会清空列表，保留策略仍按当前业务决定。

游标属于生成它的查询、排序和授权范围，换条件不能追加旧页。同一游标重复激活不追加两遍，加载失败后保留可重试游标；已加载条数不冒充全量。游标是协议定义的不透明值，用明确的“无下一页”标记，不凭字符串真假判断；空字符串在协议允许时可有效。自动重试按请求与错误类别配置，不将权限错误无限重试；后台写请求的超时仍须核对结果，前端取消和防重都不证明服务端回滚或幂等。

验证异步代码时控制请求完成顺序，而不是只增加 sleep：覆盖旧成功、旧错误、旧 finally、A→B→A、同查询换账户／权限、跨查询同游标、追加失败重试与卸载后完成。对已有缓存／路由器先确认策略，再选择相符探针。可复用的无计时探针及适配边界见 [评测说明](../evals/README.md)，来源与不采用项见 [第十二轮调研](research-2026-10-02-round12.md)。这套测试不证明页面呈现、网络取消或服务端写操作。

登录跳转保留当前意图，回来重新核对价格、权限和库存等易变条件。模拟点击用于检查路径，不能变成未授权画像、追踪或自动决策功能。

列表、搜索、输入法、URL 状态和批量操作涉及改动时，按需读 [界面模式](interface-patterns.md)，不要把所有状态机械持久化。

## 中文与内容压力

使用真实长度的中文标题、标签、段落、金额、邮箱和 URL 验证；不要只看三个短词。沿用项目字体及中文回退；价格、单位和正负号不截断。纯文本长词可适当换行，代码与可比较表格按职责局部滚动。

UI 正文、说明和元数据分开，必要费用和错误不能缩成极小灰字。标题简洁不等于删除帮助；研究中的求解器、误差、假设与来源保留必要准确性。按钮写动作和对象，不输出 TODO、开发计划或冒充真实数据的“演示成功”。

## 响应式与材料退化

多栏按任务重排而非整体缩小；不通过隐藏登录、费用、规格或主操作掩盖拥挤。检查软键盘、固定底栏、对话框和滚动区域的关系；实体设备未测就不声称这些都正常。

减少动效后保留即时状态变化；减少透明或禁用滤镜后使用实色；强制颜色模式使用系统颜色和可辨边界，不用 forced-color-adjust:none 强行保留品牌。主文字、表单与焦点不能依赖阴影或背景图才可辨认。

## 参考标准

以实际控件语义选择 [WAI-ARIA APG 模式](https://www.w3.org/WAI/ARIA/apg/patterns/)；焦点可见、遮挡与目标尺寸按 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 的适用条款判断。模式参考和单项测试都不是整站合规认证。
