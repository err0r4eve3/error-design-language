# 组件契约：角色、范围与状态

当共享组件在不同页面变样、同级对象黏连、选中与禁用混淆，或要把已验证手法抽出来复用时读取。先用 [视觉校准](visual-calibration.md) 定位问题，再确定组件负责什么；不要因这份文档给所有任务新增组件库、框架或审批步骤。

## 不按“长得像”合并

复用的依据是相同语义、输入输出与交互，而不只是相同圆角。静态金额、单选套餐、可跳转项目卡都可能有背景，但不能共用一个默认整块可点击、统一 hover 的 `Card`。必要时共享低层表面样式，把选择、导航和静态阅读的语义留在各自组件。

反过来，同一个状态在列表、详情和提示区应复用稳定的名称与符号，而不是在三个地方分别手调颜色。新增 token 或变体应解决已出现的复用或一致性问题；不要按“出现三次必须抽取”机械决策，也不要把一次性的特殊构图变成全站 API。共享修改需覆盖已知调用方，局部例外不扩大成迁移。

动手前最少确认五项：对象、数据口径、操作范围、可能共存的状态、哪一层拥有焦点和副作用。可直接在现有代码／设计说明中确认，不要求另写模板文件。

## 行内信息先分槽位，再做装饰

用于导航列表、设置项、资源行和选择器。先分清主标签、必要描述、前置识别、尾部信息与独立操作，再决定排版；槽位是职责，不要求创建同名组件或填满每个位置。

主标签承担识别；短补充可同行，解释或限制较长时移到下一行，不和标签、金额、状态争同一条基线。尾部计数／快捷键／状态各有稳定对齐位置。数量位数、长中文或较窄容器出现时，优先换行必要描述；只有能通过键盘和触摸取得完整内容的辅助文本才允许截断。金额、状态含义和决策限制不能只剩省略号或 hover tooltip。

前置图标只有在帮助辨认类型、对象或状态时才保留。同类对象不用重复无信息图标，也不为对齐添加假徽章；图标缺席时在相关列表内保持文字列一致，不把空槽推广成整站固定留白。非颜色分组规则继续适用。

**尾部信息不是尾部按钮。** 箭头、数量和快捷键可仅表达预期，不因此获得独立点击区；真正的复制、更多或删除有独立语义、名称、焦点与事件边界。行主操作和次操作不能互相触发，不在 button／链接里嵌套另一交互控件。复制编号不应同时打开详情，打开菜单不应顺便选中整行。

选择控件的 option 与独立命令也不能随意拼接。listbox 选项不塞第二个可聚焦按钮；菜单扩展按其对应键盘模式设计。需要多个独立操作时，沿用支持该结构的列表、表格或既有复合组件，不能为了复用一个外观强加不匹配的 ARIA role。Primer 的具体组件限制不是所有菜单的普适禁令。

本节来自 Primer ActionList 的槽位与角色区分，适用条件、源码版本和不照搬项见 [第十一轮调研](research-2026-10-01-round11.md)。它细化行内关系，不要求所有页面采用 ActionList。

## 视觉权重服从操作范围

| 操作范围 | 通常放置 | 防止的混淆 |
|---|---|---|
| 项目／页面 | 页头或当前任务入口 | 创建项目按钮不挤进某个列表行 |
| 当前集合 | 紧邻集合标题的工具区 | 筛选、排序、导出应说明作用于哪个集合 |
| 已选择子集 | 选择后可见的操作区，保留取消选择 | “全部”不能暗指后台所有对象；数量与范围同时可见 |
| 单个对象 | 对象内部或其对应行 | 单条读取、重试与删除不伪装为全局操作 |

范围不是单靠按钮颜色传达。先建立空间归属和准确措辞，再分主、次、轻操作；不能每个小区都放一个同等重量的主按钮。相同动作的措辞保持一致，不为追求区分度给同一结果随机换名。批量操作正在处理时，按真实业务约束限制冲突动作，不机械禁用所有行。

这张表是决策指导。当前 [组件样例](../assets/regions.html) 演示单对象读取和本地选择，没有实现集合导出或批量操作。

## 把状态拆成正交维度

不要用一个 `status` 同时表示对象生命周期、请求进度和当前选择。实际项目沿用已有数据结构，关键是含义分开，不强制变量名。

| 维度 | 例子 | 不允许的推断 |
|---|---|---|
| 对象事实 | 运行、维护、状态未知 | 读取失败不能推断对象故障；读取成功也不等于对象运行 |
| 请求阶段 | 未发起、处理中、失败、完成 | 等待请求不能覆盖上一次仍有效的对象事实 |
| 交互选择 | 未选中、已选中 | 焦点／hover 不是选择；选中不意味着不可操作 |
| 可用性 | 可操作、不可用，及其原因 | 数据未知不是禁用理由，禁用也不能仅靠降低整体透明度 |
| 数据覆盖 | 已读取数量、缺失来源、时间窗 | 状态查询不能顺便填补未知价格、额度或趋势 |

例如“服务仍为维护中，同时刷新请求失败”和“已选中一条未知状态的对象”都是合理组合。新增组合时检查信息是否互相覆盖，而不是把所有可能状态做一遍笛卡尔积。账户／权限切换仍遵守数据隔离，不能以保留旧事实为由泄露另一账户信息。

只对需要通知的动态结果设置适当的 live region；不要把每个静态状态标签都设为 `role="status"` 或 `alert`。通知包含对象和结果，避免只读出孤立的“完成”；正常刷新不抢焦点，紧急中断与表单纠错另按 [交互契约](interaction-contracts.md) 处理。使用原生 radio、checkbox 等已有语义时，不再维护一套平行的 `aria-checked`／CSS 选中状态。

## 可选实现，不是强制主题

[regions.css](../assets/regions.css) 复用已有 [tokens.css](../assets/tokens.css)，无应用壳层或全局 reset。按钮另加载 [components.css](../assets/components.css)。

- `.dl-metric-grid` 与 `.dl-metric`：同类静态指标共享表面，分别收拢标签、值、单位和覆盖说明；通过间距与独立表面成组，不增加假点击线索。
- `.dl-choice` 与原生同名 radio：选中、禁用和键盘焦点各自从原生状态派生。标签区域扩大操作面积，不隐藏原生选择标记；控件旁保留不可选原因。
- `.dl-state`：本样例只定义维护与未知两种对象状态。文字、图标路径与轮廓共同表达；没有声称提供完整状态枚举。
- `.dl-request`：单对象读取反馈，独立于 `.dl-state`。演示第一次读取失败、重试返回维护状态，并保护重复激活和重置后的迟到结果。

默认样式使用灰阶；只有同一个 `data-design="error"` 容器显式设置 `data-status-color="semantic"` 才开启小面积维护语义色。`mono` 或省略该属性不着色，不用全页灰度滤镜误改品牌图片。现有主题优先映射语义，不直接叠入第二套 token。要加其他状态，先补含义、符号和对应主题检查，而不是靠类名猜服务是否正常。

`regions.html` 是组件文档，各分区是独立用例，不是同一账户汇总。文档可以解释运行方式；这些说明和测试数值不能搬到业务页的标题、副标题或页脚。继续遵守 [产品文案边界](product-copy.md)。

## 样式所有权与局部主题

两个组件单独正确，不代表它们的 CSS 同时加载后仍正确。共享类名只表达一致契约；紧凑文字标签与带独立图标的标记若结构不同，应有明确变体或不同样式所有者。已有 CSS Modules／组件作用域优先；原生 CSS 使用项目命名边界，不为修一个冲突强制引入构建工具。检查后加载路由、可选样式和重复加载，不能仅靠规定某一加载顺序或叠加 `!important` 掩盖冲突。

状态文案、数据枚举和辅助技术含义可一致，呈现尺寸不必共用同一选择器。同一标记只由一处生成：已有 SVG 图标时，另一模块不能再用同名类的 `::before` 叠加圆点。删除伪元素之前先确认它不是其他组件唯一的非颜色线索。

主题要明确默认、继承与覆盖边界。外层语义色不能穿过内层明确的灰阶配置，深色内层也不能继续使用浅色文字配色。优先在边界解析前景／背景 token，再让组件消费；不要让每个匹配祖先的后代选择器争夺最终颜色。检查外浅内深、外深内浅、独立同级主题，以及外层切换时内层显式配置是否保持。

通过 portal 渲染的内容还需恢复所属主题：逻辑事件或焦点归属不自动恢复 CSS 继承。沿用宿主的主题 Provider／挂载点／token 桥接，不将私有作用域简单扩大到 body。此项只在实际涉及 portal 时验证，不给普通静态组件增加主题框架。

本项目紧凑清单标签使用 `.dl-collection-state`，独立图标状态仍用 `.dl-state`。复制旧清单样例后升级需同步 HTML 和 CSS，不只换样式文件。`regions.css` 的每个 `data-design="error"` 是新边界：省略 `data-status-color` 或设为 `mono` 使用灰阶；设为 `semantic` 才启用该主题的维护色。普通包装层不创建边界。详见 [第十三轮来源与复现](research-2026-10-02-round13.md)。

## 复用后检查什么

先看最常见状态，再看会改变操作后果的组合。确认同级对象在当前容器里仍成组，选中／焦点／禁用可分辨，主题切换不改变数据，错误不冒充对象事实，重试和迟到结果不会改错对象。窄屏和长内容检查使用组件实际容器，不只看全屏样张；同意图的相同样式是合法的，不用“颜色必须不同”作为判定。

`node tests/regions.cjs` 是可选样例回归，不是模型评测或美观评分。几何与像素值只约束本样例已确定的关系，不把它们推广为任意页面的合格阈值。测试包括去掉间距和隐藏焦点环的负向注入；截图还需实际查看，且读屏、真实设备、真实接口另有验证范围。

涉及上述组合时可运行 `node tests/style-composition.cjs`，使用真实样例节点与计算样式比较；它不替代实际应用的主题传播、Portal 和完整页面验证。
