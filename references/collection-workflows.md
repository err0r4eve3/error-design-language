# 集合工作流：筛选、选择与连续查看

用于订单、服务、任务、日志等集合页的优化。小修复不强制加载本文件；文章、营销页也不因此增加表格或侧栏。相关来源与实际阅读范围见 [同类产品对照](research-2026-10-01-round8.md)。

## 先决定用户是否需要留在集合里

频繁识别对象、核对少量属性时，考虑列表旁的非模态详情；用户仍能查看其他记录，避免每次打开、关闭遮罩。深度配置、长内容与独立分享通常适合详情页；有阻断意义的确认或独立小任务才用模态对话框。不要把“侧栏好看”当作通用选型理由，也不同时堆帮助栏、检查栏与聊天栏。

概览进入明细时，携带真正适用的对象、筛选和时间范围；不要让用户点进去后重新寻找同一批数据。没有细粒度数据就保持静态，不能为了模仿产品给每个指标添加假跳转。不同时间窗的账单与监控不要共用一个看似控制全部区域的日期选择器。

## 三类当前状态不能共用一个 selected

- **结果范围**由已提交的查询、筛选及权限决定。输入法组词文本尚未提交；切换另一个筛选也不能提前消费临时拼音。
- **批量选择**是当前允许操作的对象 ID 集合。明确本页、当前结果还是全量；筛选变化时保留或清除由产品规则决定，必须可见且不能悄悄作用于隐藏对象。排序通常只改变顺序。
- **当前查看对象**是一个稳定 ID，不是行号，也不等于已勾选集合。仅浏览详情不能改变勾选；勾选其他记录不能偷偷替换正在查看的对象。

详情标题、字段、状态、操作与返回目标绑定同一 ID。排序后仍是原对象，上一项／下一项按当前结果的实际顺序计算。对象被筛掉、删除或权限改变时关闭／清空详情或明确提示其已不在当前范围；禁止留着上一对象信息。任何恢复都不得跨账户泄露旧数据。

## 把空间留给对象，把操作放在其作用范围附近

页面标题说明“在哪里”；集合工具栏承担搜索、过滤、结果数量；行内入口承担单对象查看。活动筛选用可移除的真实条件呈现，移除其中一个不清空其他条件；隐藏来源必须仍能解释“为什么只剩两条”。没有活动筛选就不放空标签占位。

批量操作在存在选择时出现，与数量、必要的金额覆盖及取消选择在同一组。没有选择时不要永久摆一排失效按钮，更不能让每条记录都重复批量命令。部分价格只显示“已知合计＋覆盖数量”，不能用零补缺失后标作完整账单。生成文件与确认保存到用户设备是不同结果；导出失败保留选择，并提供可持续看到的恢复提示。

表头、行内数据、状态与操作各有权重。通过名称／编号的层级、数字对齐、合理列宽和重复行节奏提高可扫描性，不靠把所有正文降成 11px。有角色的边界可以保留；不要为“无边框”损失输入边界或对象归属。选中、当前查看和 hover 也分别检查；通用 hover 不能抹掉已打开对象的识别。

## 详情面板不等于贴在边上的弹窗

非模态详情使用与文档关系相符的区域语义，不加 `aria-modal`、全页 inert 或焦点陷阱。显式“查看详情”后，可将焦点移到详情标题；关闭后回到该对象的入口。搜索输入或后台刷新导致内容变化时，不擅自夺走当前输入焦点。只在面板内处理关闭快捷键；先让输入法、原生控件和已消费的事件处理，不能拦截全页输入。

面板标题用完整对象名，关闭控件不要挤出一个孤立的末字。字段可以直接按键值排布，不必再套等高小卡。桌面空间足够时并排，否则让详情进入文档流或采用已有的移动详情方式；不要一边称为非模态，一边用遮罩盖住整个集合。单对象阅读也可使用明确可返回的窄屏详情视图，但须保留集合状态与比较路径，不伪装成模态窗口。窄屏保留必要列及可发现的局部滚动，不能把数据裁掉后宣称自适应。

滚动提示和额外 Tab 停靠只在实际溢出时出现；窄视口不是唯一判断依据。非模态布局改变后，同时检查视线对应、键盘顺序、关闭返回和页面滚动位置。

分栏模式、滚动上下文、可见焦点、键盘优先级与真实历史导航的区别，按需见 [连续导航](continuous-navigation.md)。

## 最小验证路径

用两条容易混淆的记录核对：勾选 A → 查看 B → 改排序 → 查看相邻记录 → 关闭。选择集合、面板对象、顺序与返回目标都应独立正确。再测试筛掉正在查看的对象、只移除一个筛选、未知价格、导出失败，以及中文组词中改变状态筛选。

同一数据和视口记录改前与改后；检查真正减少了找对象或恢复上下文的步骤，而不是只换颜色。截图证明呈现，操作检查证明局部行为，不能据此宣称用户任务更快或模型质量提升。本仓库 [清单样例](../assets/patterns.html) 实现其中一条离线流程，不规定所有项目采用同样布局。
