# 视觉校准：先诊断，再选择手法

用于已有页面“太平、太乱、没有区分、重点不对、手机难用”的反馈。先读目标、邻近组件和真实状态，保留用户认可的部分。这里给选择依据，不新增固定风格、必装工具或必写设计文档。来源与不采用的规则见 [本轮调研](research-2026-10-01-round6.md)。

## 不同问题，不用同一种修法

| 可观察的问题 | 先核对 | 最小有效改法 | 反向检查 |
|---|---|---|---|
| 不知道先看哪里 | 主任务是否与最大元素一致 | 提升一个目标的字号、位置或面积，同时降低无关竞争 | 不把每个数字都放大或反色 |
| 两个指标连在一起 | 标签、值、单位和说明各归谁 | 各自成组，增加组间距或共同边界；必要时独立实底 | 同类指标可以同底同形，不要求每块异色 |
| 状态看起来相同 | 含义、证据时点和可采取动作 | 固定标签与符号映射，必要时辅以语义色 | 不把未知推断为失败，动作与实际结果一致 |
| 静态内容像按钮、选中像禁用 | 容器角色与可操作语义 | 去掉假 hover／箭头，或给真实控件完整状态；选中保留明确标记 | 不靠“变浅”同时表达选中、辅助和禁用 |
| 页面很吵 | 是否所有区域都在争主位 | 减少重复强调和容器，保留一个任务锚点 | 不降低关键文字可读性，不撤必要边界 |
| 窄屏能放下但不好用 | 同一任务是否需同时比较或编辑 | 按任务重排，保留主操作、活动筛选和比较关系 | 不以隐藏字段、缩小字体或全局 overflow 掩盖问题 |

先判断问题出在局部规则、组件变体、共享 token，还是信息组织；修最小负责层。一个例外不建立全局 token；多处同义状态失配也不分别打补丁。只有主对象或阅读顺序确实不成立，且有对应授权，才重做信息架构。

“更醒目”与“更克制”是两个方向，不是两套主题。前者放大现有语言中有用的一种手法，后者减少竞争；两者都不能改变用户要求保留的品牌与已完成区域。没有实质缺陷时不制造改动。

## 三组改前／改后：学关系，不照抄样式

以下是校准示例，不是可直接搬入产品的说明文案，也不要求每个页面复制同一种结构。

### 1. 选中与查看：先区分含义，再区分外观

**改前**：偶数行使用 hover 底色，选中仅比它深一点，勾选框以外的选择线索很弱。

**改后**：连续白底行用细分隔线；已勾选行保留复选框，并给出持久选中底色和明确行边界；查看中的对象仍以名称旁竖线及“查看中”按钮定位。所有行预留同宽边框，选择时只改颜色，不挪动点击目标。

**原因与检查**：这分别回答“会被批量操作的是谁”和“现在看的是谁”。移开鼠标、换主题、强制颜色后都应能分别回答；改变 hover 不得抹掉选择。不提供整行操作时，不给整行假 hover 或手形光标。

### 2. 两个同级指标：共享语法，不共享一团空间

**改前**：“出站流量 128 GB 月费合计 32 USD”挤在一块相同字重的灰底内，靠竖线勉强分开。

**改后**：每个指标有自己的标签、数值、单位及口径；组内紧凑，组间距离明显更大。两个同级指标可以同底同形，数字对齐；需要强调容量关系时仅对有真实分母的流量加额度轨，月费保留周期和覆盖范围。

**原因与检查**：区别来自归属与数据关系，不是随机换底色。假定有明确授权的演示数据，金额可写“32 USD／月 · 3/4 项有价格”；真实数据未读取时仍写未读取，不从样例补齐。窄屏换行后单位与口径仍紧邻自己的数值。

### 3. 副标题与未知：给用户事实，不交付开发总结

**改前**：标题“资源管理中心”，副标题“支持响应式布局、批量操作和完善状态展示”；未读取的价格显示“0.00”，维护和未知都用灰点。

**改后**：标题直接写“服务清单”，无必要则省略副标题；表格附近保留实际币种、价格覆盖和筛选范围。已确认维护写“维护中”及已知时间，尚未读取写“状态待确认”，各用稳定的文字与形状。仅有刷新能力时才给“刷新状态”操作。

**原因与检查**：能力说明不是用户当前需要的事实；未知也不是零或维护。检查标题、tooltip、无障碍名称及页脚，不能把开发说明藏到另一处；参考文档可以解释实现，但产品页面不借此例外自评。

## 表面角色与交互角色分开

在已有 token 上写清下面的对应关系即可，不要求逐项建立新的 CSS 变量。**颜色值不相等不是分组成功；相等也不等于分组失败。**

| 角色 | 应让用户读出的关系 | 不应暗示 |
|---|---|---|
| 画布／辅助工作区 | 页面环境与任务空间 | 浅灰内容全部不可用 |
| 静态内容组 | 这些标签和数据属于一个对象 | 整块可以点击、拖动或选择 |
| 可交互面 | 有明确目标的操作，含键盘焦点与可见反馈 | 任意 hover 都等于持久选中 |
| 选中项 | 当前对象或选择结果，必要时有勾选／指示条 | 禁用、失败，或鼠标移走即失去选择 |
| 浮层 | 临时覆盖在当前任务之上 | 仅靠极高 z-index 就完成背景隔离与焦点管理 |
| 语义状态 | 生命周期、请求结果或证据缺口 | 同一种小灰点代表一切 |

灰阶基底不强制删除有用的品牌色、分类色与状态色；是否采用由本次要求、任务与非颜色线索决定，不限于危险或安全场景。严格无彩色时遵守该约束，用文字、符号、轮廓、填充与分组承担区别，不偷偷加“少量例外”。

深色不是浅色反转。检查内容面、辅助面、选中、禁用、浮层在**实际相邻背景**上的区别；暗底上阴影不明显时，使用项目许可的表面明度或边界。不要要求所有深色页面都套一套高度模型。本仓库 `workspace` 只是辅助工作区，不能因名字就当作两主题都更暗的凹入面；需要真实凹入语义时才另行映射。

本仓库清单对 selected 与 surface／hover 采用 **1.15:1 内部回归下限**，只防止相竞争的填充再次挤在一起，不代表 WCAG 达标，也不是所有语义 token 两两不同的要求。正文与次要文字对实际背景检查 4.5:1；用来识别状态的必要边界对相邻色检查 3:1。填充之外仍保留复选框等明确线索，强制颜色另测。依据见 [WCAG 非文本对比说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)；此处不是完整无障碍认证。

同级可重复，相异要有理由。三张同类套餐卡用一致样式和清楚间隔即可；仅把被选套餐加选中标记。流量与月费可以使用不同表面，但不能把这次样例推广为所有指标必须异色。操作按钮同一结果用一致措辞；不同状态不强迫不同按钮名。“刷新状态”必须真的发起读取，不能只是打开详情。

## 密度不是把字号变小

先删重复摘要、重复入口和开发解说，再决定哪些信息能延后。需要所有人据此作决定的信息就地保留：对象名、状态、当前筛选、金额／周期、重要限制、数据覆盖和关键动作。多列不必等宽；数字、标签、操作各按内容分配空间。不要为整齐给不同语义内容同样的高度。

仅少数用户需要的诊断、参数说明可进入详情或折叠区，入口写具体对象。不能把帮助做成第二份功能清单，也不以“高级设置”掩盖本来必填的配置。副标题不是填满留白的材料，继续遵守 [产品文案边界](product-copy.md)。

**必须同时比较的内容不要拆进互斥标签页**；顺序阅读的步骤不靠 tabs 假装流程。长列表可局部滚动或分段；移动表格只有在单条检查是主任务且列名／关联仍清楚时才考虑卡片化。比较任务保留二维关系和可发现的局部滚动，不强制所有表格变卡片。折叠不应导致用户失去活动筛选或必需的费用条件。

视口宽不等于鼠标，视口窄不等于仅触摸。必要操作不能只在 hover 出现；键盘、触摸和混合输入有可达路径。视觉重排与阅读／焦点顺序保持合理；缩小窗口只验证布局，不能证明真实触摸拖动、软键盘或系统输入法可用。

## 不同的“没有内容”需要不同恢复

| 证据 | 保留什么 | 合理的下一步 |
|---|---|---|
| 成功读取，确实还没有对象 | 页面身份和创建条件 | 有权限时创建首个对象；没有创建能力就解释来源 |
| 成功读取，当前筛选无匹配 | 搜索词、活动筛选与可修改入口 | 修改／清除筛选，而不是推销创建对象 |
| 尚未读完或正在刷新 | 请求状态；按业务允许保留已有内容 | 等待可见结果，必要时取消；不闪现假空态 |
| 部分来源失败或只有旧数据 | 已知数据、范围与更新时间 | 重试失败部分；不可当作最新或完整数据 |
| 无权读取 | 权限边界，不泄露受限内容 | 已有流程中的切换账户或申请权限；不假造申请入口 |
| 请求失败且无可用内容 | 本次读取失败及输入上下文 | 可恢复的重试，不把服务判为宕机 |

这些是 UI 判断，不授权缓存跨账户数据。账户、权限或对象变化后先隔离旧数据，不能以“保留内容更流畅”为由展示前一账户信息。复用已有旧数据必须满足权限与业务规则；标注旧数据不是绕过权限的理由。

## 参考要有可迁移的理由

研究成熟产品时，优先选任务、数据密度和状态相近的页面，不只挑好看的首页。记录：来源与版本／日期、实际看到了什么、采用的一个关系、目标组件、怎样检查。文档文字只能证明作者指导；截图证明可见状态；登录后的真实行为要另有授权与实际操作。不要把其中一种证据补写成另外两种。

借鉴“列表与详情怎样保持对象关系”，而不是抄完整壳层；参考页有图表也不证明我们有相应数据。少量近似案例比大量无关素材更有用。项目已有完整确认稿时不再以调研为由自由换风格。

改后检查目标局部与相邻区域，在相同数据、主题、尺寸下比较。必要时去色或隐藏**装饰**线，但不删除必要控件／对象边界再宣告失败。文字、几何或颜色断言只能守住已知回归；实际截图观察、用户任务验证与模型对照实验分别报告，不能相互冒充。
