# 排版与界面细节

按问题读取相关小节，不把整份清单强加给局部修复。以下尺寸是本 Skill 的可调起点，不是外站测量结果或通用合规门槛。来源与取舍见 [调研记录](research-2026-10-01.md)。

## 先让页面像它所服务的任务

操作台把对象、筛选、状态与动作放在第一工作区；阅读页让标题、目录和正文建立节奏；展示页让真实作品或产品成为视觉中心。同一个产品的首页和控制台可以使用不同密度，不能因为品牌相同就都加 hero。

一页的识别点可以只是精确的字阶、列对齐或一个真实产品图形。选一个有内容依据的重点，其余安静。没有步骤关系就不加 01/02/03，没有分类意义就不加 eyebrow；不能把全站圆角清零、单词随机着色或换成衬线字体当作“去模板化”。

## 工作区的骨架

先对齐页面标题、工具栏、表头和第一列；表头描述对象，工具栏控制当前集合，行操作作用于该行，批量操作只在选择后出现。搜索不要占据与主内容无关的独立巨卡片。

短标签紧跟控件，帮助贴近输入；同一分组内距小于组间距。用间距已经能分组时，不叠加边框、背景、阴影和嵌套卡片四重强调。宽屏增加有效信息或合理留白，不把短字段拉成无限宽。

紧凑不等于小字：先减重复标题、冗余元数据和无效容器，再减少行距。鼠标密集表可尝试 36–44px 行高；触控、两行内容或含复选框时以实际点击区域和换行决定高度，不能强行固定。默认移动目标仍见 [数值与材料](visual-system.md)。

## 中文、数字和长内容

- 保留现有字体与中文回退，先校正字号、字重、行高；不要为“高级感”全站换字体。正文与控制文字分别设置，英文标题的负字距不能机械套给中文。
- 标题自然换行；`text-wrap: balance` 仅是渐进增强，不用大量 `<br>` 锁死一个视口。长正文不用 `word-break: break-all`；长 URL/标识符在自己的容器使用 `overflow-wrap: anywhere`。
- 比较列使用 `font-variant-numeric: tabular-nums` 与右对齐；正文仍用比例字体。金额展示币种和周期，单位与数值保持相邻，但不要把整行设成永不换行。
- 未知、零、不适用分开。排序依据原始数值／时间戳，不依据带逗号和币种的展示字符串；跨币种无明确换算依据就分组，不直接混排。
- 只有可恢复完整内容的次级信息才能省略。价格、错误、权限、主按钮名称不截成省略号；原生 `title` 不能作为手机和键盘取得全文的唯一方式。

检查短、正常、极长三种内容，而不是只看英语占位词。增加文字间距后的不裁切能力与默认排版是两回事；[W3C 文字间距说明](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html) 不要求把其测试值设为默认。

## 方向、技术短语与嵌入尺寸

组件进入其他页面时，界面方向、文字片段方向和键盘行为分别核对。保留当前已确认的语言与布局；只有任务涉及多语言或可复用组件才扩展方向检查，不据浏览器语言擅自翻转产品。DOM 的 `dir` 与已有库的方向上下文应来自同一配置，局部声明优先；仅有 React Provider 不保证 DOM 已设置方向，`lang` 也不代替 `dir`。

逻辑位置与预留空间必须配套。例如单选点使用 `inset-inline-start` 时，文字应使用相应的 `padding-inline-start`；不能点在右边、空位仍在左边。优先按有效方向自然布局，不用针对任意祖先 `[dir="rtl"]` 的选择器压过内层 `ltr`。也不要把所有物理坐标机械替换：金额比较列、图表坐标、照片和品牌图形按其任务保留，箭头只在语义确实改变时镜像。

方向相反的短语作为一个单元隔离。已知规格可写 `<bdi dir="ltr">2 vCPU</bdi>`，数字与单位放在同一包裹内；方向未知的外部名称按场景用 `bdi` 或 `dir="auto"`。不要倒置源字符串或往复制值里塞不可见方向字符来修正显示。`textContent` 正确不证明视觉顺序正确；检查必要标点、数字和单位的实际渲染。这是排版规则，不是内容安全过滤。

可复用控件先在实际容器宽度检查，再做视口断点。宽屏侧栏里的 220px 组件仍然很窄；单独检查局部方向覆盖、长文案、较大文字、原生禁用和焦点，不能只把整个浏览器缩到手机尺寸。输入命中区与文本不要互相覆盖；必要字段不能用截断掩盖。已有布局能处理就不强制新增容器查询、国际化库或布局框架。

优先沿用原生控件或项目现有方向感知原语，不全局重映射左右键。重复单选组需按其表单与业务组分配名称，主题／方向容器不会自动隔离同名 radio。方向变化只改变呈现，不能重置选择、修改价格或改变请求范围。源码依据、局部修复与未测范围见 [第十四轮调研](research-2026-10-02-round14.md)。

## 图标、边界与表面

图标沿用同一家族、stroke/fill 和光学尺寸；16–20px 可作紧凑 UI 的起点，不等于点击区域。图标与文字按视觉中心微调，先查 SVG viewBox 的空白再用偏移补偿。装饰 SVG 隐藏于辅助技术，图标按钮仍需表达动作的名称。

灰阶状态用文字、选中标记或形状区分；不要用四个几乎一样的灰点代表运行、故障、暂停和未知。hover 是短暂反馈，selected 是持久选择，focus 是键盘位置；三者不能共享一个难以区分的暗底。

相连内容靠分隔，悬浮表面靠边界、位置与少量阴影。玻璃只增强辅助壳层；背后滚动内容复杂时先提高实底比例，不为透射感牺牲文字。阴影在强制颜色模式下可能消失，必需边界不能只靠阴影。

## 响应式不是隐藏字段

布局先允许收缩：grid 用 `minmax(0, 1fr)`，flex/grid 子项设适当 `min-inline-size: 0`，工具栏自然换行。只有真的需要横向比较的表格、代码或画布局部滚动，并给区域名称、键盘入口和可见提示；不能全页 `overflow-x: hidden` 掩盖越界。

小屏仍保留对象、状态和下一步。把非关键元数据移到详情前，检查用户是否必须靠它做当前决策。固定栏必须计入安全区与滚动留白；低高度视口下可以取消 sticky，不能占满内容区。

320 CSS px 是窄屏重排检查之一，不能称作已经完成浏览器 400% 缩放或实体手机测试。[W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) 对必要二维内容有例外，但不豁免其外部标题和工具栏。

## 动效、图片和性能

反馈先成立，再加动画。菜单从触发点展开，关闭可被新操作中断；常规 hover 不让表格行、价格或整张卡片跳动。不用 `transition: all`，也不让所有段落滚入时重复飞入。

快速本地筛选无需骨架屏。慢请求可以延迟出现占位以避免闪烁，但数据已经到达就可呈现，不为凑动画时长锁住交互。减少动态效果时直接到目标状态，不保留长等待的“无动画版”。

图片用真实资产并预留尺寸，先判断裁切是否损失内容；说明图不因统一比例切掉标签。首屏关键图和屏外装饰图分开加载，字体失败仍能阅读。优化前记录同一设备、输入和网络条件；没有测量不承诺提速，不为了四条记录引入虚拟列表。

复用 [patterns.css](../assets/patterns.css) 的表格、滚动区域、数字与分组样式时，先映射既有 token；它是可选样例，不是新框架，也不要求每页采用该结构。
