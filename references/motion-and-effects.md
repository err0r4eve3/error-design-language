# 动效与效果：反馈先于装饰

仅在处理动效、引入效果组件或制作相应体验时读取。范围与状态语义仍由 [入口](../SKILL.md)、[交互契约](interaction-contracts.md) 定义；本文件负责效果选择、装饰层组合与降级，不另立异步业务模型。

## 先选它要表达什么

日常反馈帮助用户知道操作已接收、对象去了哪里、哪个区域正在处理；表现性动效用于少数确有品牌意义的瞬间。先解决任务反馈，再考虑表现。可以完全不用特效；“没有适配效果”是完成的设计判断，不是缺少功能。

同一注意区域先安排一个主要动态信号，其他内容稳定。它是克制的起点，不是禁止播放器与独立上传任务同时反馈。重点是避免同一事件让边框、球体、标题和背景全部竞争。说明状态无需等待某个秒数；也不把外部资料的2秒／3秒分界当成适用所有任务的门槛。

## 效果选择表

这些是从Libraries.dev提炼的能力类别，不是默认安装清单；选库前核对当前项目依赖、许可证、目标环境与实际类型。已有CSS／原生方案足够时不新增包。

| 意图 | 可选表现 | 必须稳定保留 | 静态或低成本替代 |
|---|---|---|---|
| 某区域正在处理 | 区域边缘光线／局部强调 | 区域身份、可见状态、停止或重试 | 静态边界＋文字；常规等待指示 |
| Agent活动变化 | 状态球／紧凑活动标记 | 真实活动名称；未知时只说正在处理 | 普通图标＋状态文字 |
| 小型控件的合并／分离 | 液态指示或表面变形 | DOM语义、命中区、焦点、选中关系 | 瞬时位置切换或简单过渡 |
| 语音输入／播放 | 随真实音频变化的局部光带 | 录音状态、开始／停止、拒绝授权恢复 | 麦克风状态＋文字，不模拟音量 |
| Agent身份识别 | 统一几何的头像 | 稳定身份、名称与可辨区分 | 静态头像／姓名，不持续眨动 |
| 已授权的品牌展示 | 局部金属／光泽材质 | 清晰的原生文字、主题与内容层级 | 实色文字或静态资产 |
| 图片呈现 | 内容就绪后的显现／去噪效果 | 原图、比例、替代文本、失败恢复 | 直接展示已加载图像 |

日常列表不逐行放持续动画，价格与风险提示不用流光制造诱导。指示条可以跟随选项移动，但不能为了形变让用户再次点击的目标漂移。效果与图标的比例、材质和颜色需映射本地表面角色；不能因为控件默认深色就把全站改黑。

## 用真实状态驱动，不表演后台

先区分已提交、处理中、结果可用、失败、取消；只显示系统实际提供的阶段。只有busy标志时不轮播“搜索、运行代码、校验”等虚构过程。已知总量用真实进度；未知就明确未知，不循环生成假百分比。装饰结束不触发业务成功，业务成功也不等于图片已经加载可显示。

效果可按“真实活动且允许动效且当前可见”运行；文字反馈独立存在。请求完成、失败或取消都停止对应效果；旧请求不能覆盖新会话。离开页面或组件卸载时由拥有资源的层清理。共享资源不能因一个装饰组件消失而被另一个组件错误关闭。

语音需在真实授权和音轨有效后才显示正在收音；暂停可视化不等于停止麦克风，停止按钮必须实际停止本会话的录音资源。区分录音、转写、播放、权限拒绝和设备失效。库的展示组件不会自动提供录音上传／转写业务，不从示例占位函数推断已有能力。

图片先处理真实URL、加载／解码和失败，再增强显现效果。服务端生成结束与浏览器图像可用是不同事件；不能用定时器猜加载完成，也不能以模糊动画伪装生成进度。效果失败时仍可直接查看原图。

## 装饰层不能改坏控件

底层按钮、输入、链接、表格与文本保持真实DOM和原有语义。纯装饰不重复朗读、不接收指针或焦点；必要反馈放在合适的可见文本和状态区域，避免每一帧都播报。流光不是焦点环，动画不是唯一选中标记。

加入wrapper后复查宽度、内边距、圆角、定位、层叠和裁切。包装一个按钮可能使它拉满整行；`overflow:hidden`可能裁掉焦点环、阴影和下拉菜单。先明确每层负责什么，再沿用项目浮层机制；不以新增Portal或高z-index掩盖一个未理解的裁切问题。液态表面移动时，文字和点击区域不能被扭曲成不可读或不可靠的形状。

局部主题优先跟随组件所处表面，而非只读操作系统主题。SSR首屏与客户端初始结构一致；不能把整个应用改成client-only只为展示一个装饰。需要浏览器API的效果放在最小边界内，服务端内容与静态替代保留。

## 动态偏好、运行成本与退出

减少动效偏好不仅是写一条CSS：Canvas、WebGL和JavaScript循环也要停用或切为静态，并响应运行中的偏好变更。关闭效果后保留状态文本、焦点和可操作内容。强制颜色模式不依赖透明渐变传递必要信息。自动播放且满足相关条件的持续动效需提供暂停／停止／隐藏机制；不得把“支持reduced-motion”等同于整项无障碍合规。

组件不可见、页面隐藏或会话结束时，明确暂停／恢复策略；在卸载时清理本实例的动画循环、监听器、观察器和图形资源。库声称自动处理的行为也需按实际版本核实，不能把一个库的省电行为套给其他库。

先试最小面积、最少实例和简单合成。变换／透明度通常是优先候选，但不保证实际性能；滤镜、模糊、混合和逐帧测量在目标浏览器检查。按本次目标记录可见实例数、滚动／输入响应、布局稳定与新增依赖，不宣称未测量的帧率、包体积或“零成本”。不能为减小首次包体积推迟必要文本或主图到不可发现。

遇到不支持图形能力、效果资源失败或用户关闭动效，降级到原生内容与静态样式。所有数据和操作路径都不能以效果成功初始化为前置条件。

## 最小验证矩阵

按本次实际影响选择检查，不为一个局部改动强制跑全部环境。

| 检查 | 可观察结果 |
|---|---|
| 正常→完成／失败／取消 | 动态标记随真实状态结束，恢复动作可用，旧会话不串写 |
| 运行中切换减少动效 | 相关JS／CSS动画停止，文字与焦点不消失，结果仍能展示 |
| 隐藏→返回／卸载 | 不残留本实例的工作循环或录音，恢复不重复订阅 |
| 浅深与局部反色 | 字、图标、静态状态和焦点仍可辨，不只看全局主题 |
| 键盘打开浮层 | wrapper不裁剪或遮挡，焦点可达并正确返回 |
| 窄屏／长文案／效果失效 | 页面无意外溢出，内容与主操作不依赖特效 |
