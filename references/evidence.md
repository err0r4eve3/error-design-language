# 依据与边界

整理日期：2026-09-30。来源为用户可访问的本地历史、应用中的相关对话、项目设计文档与当前样式。以下短引文用于追溯设计决策，不包含完整会话或运行数据。

**最新决策优先**：本次整理过程中，用户明确补充“尽量统一吧 都适用黑白灰 液态/毛玻璃”。最终 Skill 因此采用跨项目统一的灰阶与玻璃；下列暖色、珊瑚色、钨丝橙记录用于解释历史，不再作为界面配色默认值。

**后续修正**：用户指出“颜色层次不对 文字和按钮似乎不对”。原样张的主按钮中灰、选中面偏重，控件边框比正文层级更显眼，缺少独立的按钮状态配色。修订版拉开主／次／轻操作与禁用态，减轻选中底，调整文字梯度，并以浏览器最终样式验证 hover、按下、禁用和处理中状态。额外发现并修复了切换主题时文字先换色、按钮背景仍过渡的瞬间失配。基础对比达标不能替代整体层级判断。

## 已有设计与实现证据：不能当作逐项用户偏好

- **Infofetcher**：`apps/web/DESIGN.md` 与当前样式支持事件、变化、来源和未知项的顺序，以及平直的连续内容层；“参考 Ground News 优化项目”的对话支持来源对照与数据语义。无坐标不造地图属于证据约束，不冒充用户逐字说过的话。
- **IDC**：`apps/web/src/styles.css` 有画布、强文字、正文、选中态和玻璃 token；`design-qa.md` 记录浏览 → 配置 → 登录的上下文保留与模拟验证。
- **博客**：`DESIGN.md` 定义世界线、钨丝橙、实色正文与克制玻璃；品牌彩蛋是该项目特例。文档内部 blur 数值有不一致，本 Skill 没把其中任一个数值升级为全局规则。
- **Emby**：`frontend/app/globals.css` 既有基础主题，也有商店覆盖样式；必须按实际页面取 token，不能只读文件最前面的颜色就断定商店品牌。
- **SciUQ**：`frontend/src/app/globals.css` 支持黑白双主题与 ChatUI 布局。这证明当前代码方向，不证明用户对每个细节都满意。
- **PipPlay**：`styles.css` 历史上使用暖底、珊瑚色与游戏封面。最新要求将界面基底统一灰阶，但游戏画面与封面仍是内容，不能因统一而全页去色；独立封面卡片仍有角色价值。
- **教学平台**：`DESIGN.md` 是 Claude 风格参考，不能将其定制字体、颜色描述或全部数值当作当前品牌事实；直接用户纠正和实际页面优先。
- **学习助手／建模**：历史记忆支持题面、前置知识和演示边界；本轮没有对所有教学成品作逐页视觉审核。

## 本次综合建议

语义 token 命名、颜色起点、字体尺寸区间、圆角区间、动效时长与检查顺序，是为执行上述偏好整理的建议。它们可调整，不能标成“用户指定”。

过去曾使用 Google Material、Claude 暖色和 Apple 玻璃等不同方向。本次明确统一后，共同 token 与玻璃优先；如果以后用户明确要求新的方向，再按新要求调整。

## 覆盖限制

检索了项目清单、1026 条去重的本地对话标题，并筛读设计相关记录；正文范围包括 36 份标题命中的本地日志、3 份追加日志，以及应用读取的 2 个相关对话，共 41 份记录，存在继承历史重叠。两个候选旧对话无法读取，未据此补造结论。

这不是所有云端、远端与已删除对话的完整导出，也不是所有项目的线上设计审计。本 Skill 对证据不足的项目仅应用共同规则，不臆造专属风格。后续只在用户要求更新 Skill 时把新反馈写回；普通使用不自动修改持久记忆或项目规范。
