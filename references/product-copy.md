# 产品文案，不是开发汇报

修改可见文案、新建页面或清理“AI 味”时读取。本规则约束模型生成的页面；用户明确要求保留的原稿不擅改，有冲突就指出。技术产品的真实领域术语不是禁词。来源与取舍见 [本轮调研](research-2026-10-01-round4.md)。

## 硬边界

**禁止把给开发者的需求、实现过程、能力清单、验收结论或设计自评写进面向用户的标题、副标题、眉题。** 不能把这些话搬到正文、卡片尾部、tooltip、页脚或无障碍名称中来规避。开发记录留在提交说明、README、测试报告或明确隔离的开发者工具中。

“支持搜索、筛选、排序和导出”“基于 React 构建的响应式控制台”“清晰的层级与流畅交互”“所有操作均可点击”“未知值始终排末位”通常是开发汇报，不是业务页的开场白。功能真实存在也不足以让这句话进入标题。

不要为填满布局而强制配副标题。标题已经说明对象或任务，旁边的控件已经说明动作时，直接删去重复介绍；不将其润色成更抽象的口号。营销页可陈述经证实的产品能力，开发文档可以介绍实现，教程可以教操作——由页面目的决定，不按“搜索”“排序”“API”等词一刀切。

## 仓库样例的用途边界

`assets/preview.html` 和 `assets/regions.html` 是标明身份的组件参考，读者是实现者：组件名、变量说明和模拟状态操作可以出现，但“统一视觉”“精致流畅”等设计自评仍删除。`assets/patterns.html` 与 `examples/panel/` 是业务任务演示，标题、列表和页脚遵守产品文案边界。演示数据、不会收费、刷新会丢失数据等决策条件仍保留。

`data-example-kind="component-reference"` 只声明用途，不是让任意页面绕过文案审查的开关。复用组件时带走结构与行为，按目标业务重写内容；不能把参考文档的介绍和样例操作名称直接复制成产品副标题。

## 每句话先确定读者与作用

| 信息 | 合适的位置 | 处理原则 |
|---|---|---|
| 对象、任务、当前结果 | 标题、状态、操作标签 | 名称具体，动作可预期 |
| 会改变当前决定的范围或条件 | 就近辅助文字 | 保留单位、时间窗、计费周期、覆盖不足、权限、不可逆后果 |
| 输入格式或失败恢复 | 字段帮助、错误位置、错误摘要 | 在需要的地方出现，不拿主标题讲解 |
| 首次上手或少见能力 | 可关闭的引导、帮助、有名称的入口 | 不强迫熟练用户每次阅读 |
| 组件库、布局策略、测试项、模型／Skill 名称 | 开发文档与交付说明 | 不进入业务 UI，除非产品本身就在展示这些对象 |

判定问题：**用户不认识开发者、没有读过本次需求，这句话是否仍帮助他理解对象、判断状态、避免风险或完成操作？** 若否，删除。若有作用但位置不对，移到作用发生处。不要只查正则关键字。

## 删除和保留的对照

| 当前表达 | 修改 |
|---|---|
| 服务概览／查看实例状态与流量，处理需要关注的服务 | 保留“服务概览”；控件足够清楚时不设副标题 |
| 实例清单／支持中文搜索、数值排序与 CSV 导出 | 保留“实例清单”；通过搜索框、排序按钮、导出按钮提供能力 |
| 维护状态保留在清单中，便于继续跟进 | 保留实际状态与对象；有依据再写恢复时间，不解释实现行为 |
| 你的操作，只发生在这里 | 移除口号；用明确的“演示模式 · 不会收费”和必要的刷新丢失提示 |
| 5/6 台价格已知 · 非完整账单 | 保留在金额旁；不能为简洁改成无条件“总月费” |
| 输入已保留，请重试 | 保留在真实失败处；不能把失败恢复说明提前塞进首页副标题 |
| 删除后无法恢复／需确认受影响的 3 个对象 | 保留在确认操作旁，不折叠到无人会看的帮助里 |

标题不必总是名词。结果页可以写具体结论，空状态可以解释为什么没有结果。不要为避免重复而删除唯一 h1、持久字段标签、无障碍名称或手机菜单收起后唯一的定位信息。

## 文案验收

查看实际渲染的 h1–h3、眉题、副标题、段首、卡片说明、页脚，以及动态成功／错误／空状态。小任务只检查受影响路径，不逐次生成全站文案表。

每句新文案应能归入对象、动作、状态、决策条件或必要帮助。凡在解释“这个页面如何开发、实现了哪些功能、为什么设计得好”的句子都要删除或移出业务界面。标题与副标题说同一件事时先删除副标题，不寻找同义替换。

少量关键词可做风险提示；已确认页面可用文案允许清单做回归，但允许清单不是其他页面的词汇模板。保留反例：技术文档中的“支持排序”、真实账单缺口、危险确认、首次上手帮助都应按语境保留。自动检查不能证明任意文案语义正确，必须如实区分静态检查、渲染审阅和模型行为评测。
