## 实际验证

Node.js 22.16.0、Chromium 144.0.7559.96、环境已有 Playwright；无新增依赖。Browser 插件未列为可用。首次 file 导航实际被 `net::ERR_BLOCKED_BY_ADMINISTRATOR` 阻止，之后显式选择 inline fixture，没有绕过限制。

```sh
node --test tests/color.test.cjs tests/patterns.test.cjs
DESIGN_QA_MODE=inline node tests/patterns.cjs
```

浏览器另设置 `PLAYWRIGHT_MODULE`、`CHROME_EXECUTABLE_PATH` 指向已有安装，`DESIGN_QA_DIR` 指向源外新目录。默认仍为 file；失败不会自动记成通过。

## 本轮发现及修复

第一版候选在重复 setContent 后遗留 matchMedia 监听，旧闭包修改新页面并干扰滚动恢复。加入样例作用域的清理入口，同时注销媒体监听和 ResizeObserver。长列表中前方行高增加后，聚焦入口紧贴视口边缘，补 8px scroll-margin 而不是只放宽断言。测试截图改为等待布局事件和有限转场稳定，避免把进入过程的透明帧或旧布局余留当最终页面；没有把这类截图问题归咎于未修改基线。

这些修复后重新运行定向 Node、主浏览器套件及独立 probe。最终浏览器记录为 pass。先前中间失败结果保留为调试材料，不混为最终验证结果。
