状态：**not_run**。本文件是执行协议，不是运行记录，也不证明 Skill 让模型输出变好。沿用已有准备器；不再为尚未执行的实验新建一套评分工具。运行前先读 [行为评测说明](README.md)。

## 固定范围

| 场景 ID | 首要观察结果 |
|---|---|
| fix-hover-only | 只修负责层；选中、文字对比和键盘焦点没有相邻回归 |
| peer-same-style | 同级对象可以同底同形，但空间归属清楚，不被强迫换色 |
| copy-dev-brief-leak | 开发摘要不进入产品标题、tooltip、无障碍名称或页脚 |

| build-dense-console | 任务锚点、同级分组和移动比较成立，不以堆卡片或缩字替代 |

## 先冻结，再执行

A 组不安装本 Skill；B 组在同一宿主安装同一冻结版本，保留正常自动路由。两组使用相同模型版本、系统提示、工具权限、起始 fixture、时间与最大输出预算；每次都新会话、新工作副本、无前次结果或持久记忆。记录入口、实际加载的参考文件与哈希，不预加载整个仓库。模型不支持 seed 时写“不支持”，不伪造相同随机性。

每个场景运行 3 对，共 36 个独立会话。事先打乱场景与组别顺序并保存顺序，避免总是 A 先、B 后。对某个正向案例，B 未触发也是路由结果，不能悄悄手动加载后只上报成功。手动加载实验须另立实验，不能替代本轮。`backend-negative` 的结果依赖真实宿主路由轨迹，强制注入文本不能验证不触发。

记录每次的模型／宿主／版本、预算、实际输入与输出 token、耗时、读写／工具轨迹、是否触发、文件 diff 和实际验证证据。宿主不提供的用量记 `null` 并解释，不用字符数冒充 token。失败、环境阻塞与未运行保留原始状态，不挑选最好的一次。

## 判读

审查者只看去掉组别标签的输出、轨迹与同尺寸同数据的渲染，按原场景 rubric 判定。不可只用关键词匹配代替行为；视觉改善需看截图，恢复与权限问题需看实际操作轨迹。判断分歧保留并复核，条件允许时让未参与生成的人复核。

先逐场景报告 3 对的胜／平／负、关键失败类型、实际用量和耗时，再汇总描述。负向路由单列，不拿“没有设计页面”当视觉失败。3 对只提供初筛信号，不支持稳定效果、显著改善或 token 节省百分比的强结论。

发布门槛是有真实配对输出与可追溯记录，而不是该计划、JSON 或页面测试通过。首轮没有改善时，优先删掉无收益的重复规则，再增加规则；对相邻范围造成负作用时单独做该规则的消融。
